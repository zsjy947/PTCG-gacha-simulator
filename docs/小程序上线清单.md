# 微信小程序上线清单

> 本清单对应 `wechat-miniapp` 分支的 `miniprogram/` 工程。按顺序执行，
> 备案是耗时最长的硬性项，应在开发启动时就提交。

## 一、动手前必须想清楚的两个风险

1. **IP / 商标风险（最大的一票否决项）**
   - 卡图与"宝可梦"名称属于 Nintendo / Creatures / GAME FREAK / The Pokémon Company。
   - 小程序是微信公开生态，被投诉会直接下架甚至封禁主体，风险远高于 GitHub 分发的 exe/APK。
   - 必须做到：名称、简介、关键词、头像、页面文案全程不出现"宝可梦 / Pokémon / PTCG"等商标词。
   - 工程内已默认使用中性名称「卡牌拆卡模拟器」，后续运营也请保持低调（弱化分享传播）。
2. **类目审核风险（抽卡类内容）**
   - 绝对不能选「游戏」类目：游戏类目要求出版备案（版号），个人主体根本无法选择。
   - 定位为**工具**类（工具 > 效率 / 信息查询），功能描述统一说"卡牌信息查询与收藏模拟工具"。
   - 保留概率公示页（合规加分项）；消费统计措辞保持"模拟参考"；无任何付费/抽奖转化路径。

## 二、账号与资质

- [ ] 注册小程序账号（[mp.weixin.qq.com](https://mp.weixin.qq.com)），个人主体即可（免费、无认证费）
  - 个人主体限制：不能开微信支付、不能发广告位变现；如需企业主体请提前注册企业
- [ ] 拿到正式 `appid`，替换 `miniprogram/project.config.json` 里的 `touristappid`

## 三、小程序 ICP 备案（硬性，最耗时）

- [ ] 2023 年 9 月起新小程序上线前必须完成备案，在微信公众平台「设置 → 基础设置 → 小程序备案」提交
- [ ] 准备：主体信息、负责人身份证、人脸核验、联系方式
- [ ] 管局审核一般 1~4 周 —— **先提交备案，再并行开发**

## 四、名称 / 头像 / 简介

- [ ] 名称避免一切商标词（含拼音缩写），建议方向：「XX 卡牌信息查询」「XX 收藏模拟工具」
- [ ] 头像用自绘图形（卡背 / 抽象图形），不用官方 logo、精灵球、卡图
- [ ] 简介与功能描述贴工具类目，出现"开包/抽卡/出货"等词被驳回概率高，用"模拟演示 / 信息查询"

## 五、域名配置（mp 后台 → 开发设置 → 服务器域名）

本项目架构已把网络依赖压到最低：

| 用途 | 域名 | 协议 | 是否必须配置 |
| --- | --- | --- | --- |
| 卡图/弹图标 `<image>` 直连 | `https://tcg.mik.moe/static/...` | HTTPS | **不需要**（image 组件不校验域名白名单） |
| 卡牌详情文本 `wx.request` | `https://tcg.mik.moe/api/v3` | HTTPS | **需要**：加入 request 合法域名 |

- [ ] 在后台把 `https://tcg.mik.moe` 加入 request 合法域名
  - 注意：域名需 HTTPS 且**已 ICP 备案**；mik.moe 为社区维护站点，若备案校验不通过，
    详情功能会自动降级为卡表基础信息（页面已做兜底），可接受则无需额外处理；
    彻底方案是后续接微信云开发做一个转发函数（无需域名白名单）。
- [ ] 未配置时的表现：详情弹窗显示"详情接口不可用"提示，其余功能不受影响

## 六、用户隐私保护指引（随版本提审强制）

- [ ] mp 后台「设置 → 服务内容声明 → 用户隐私保护指引」填写：
  - 本项目仅使用**本地存储**（`wx.setStorageSync` 保存收藏/统计/设置），据此声明"存储信息"
  - 未使用位置、相册、录音等敏感接口，无需额外声明

## 七、提审前技术自查

- [ ] 微信开发者工具打开 `miniprogram/`，真机预览：
  - 四个页签可用；选弹 → 开包 → 翻卡 → 记录/收藏/统计落库
  - 卡图能加载（若 mik.moe 挂了或防盗链，考虑把图源切到云存储）
  - 深浅色切换正常
- [ ] 包体积：上传时确认主包 < 2MB（构建脚本会打印 cards.js 体积，约 1MB）
- [ ] `project.config.json` 的 `appid` 已替换；`urlCheck` 提审前建议改为 true 验证域名校验
- [ ] 移除/关闭开发期调试配置；体验版全量回归一遍

## 八、提审与发布

- [ ] 上传代码 → 填版本描述（强调"数据查询与收藏模拟工具、概率公示、无支付"）
- [ ] 提交审核，类目截图与功能一致性（首页不能出现"游戏"暗示词）
- [ ] 被驳回常见原因：类目不符 / 涉抽卡暗示 / 名称侵权 —— 按驳回意见调整文案重提
- [ ] 审核通过后发布；后续卡表数据更新走 `tools/build_miniprogram.py` 重新构建上传

## 九、与 exe / APK 端的关系

- 引擎同源：`shared/gacha.js` 唯一权威实现，三端共用，Python↔JS 有同种子对拍测试保护
- 数据同源：`python tools/build_miniprogram.py` 从 `data/` 生成小程序内嵌数据（字段裁剪到最小集）
- 本地存储键名与 exe / APK 端一致（`ptcg_coll` / `ptcg_stats` / `ptcg_history` / `ptcg_spend`），
  收藏册 JSON 导出互通

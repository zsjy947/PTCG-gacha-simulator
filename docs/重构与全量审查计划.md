# PTCG 重构与全量审查计划

> 基线：`dev` 分支 @ b4b080b（v1.3.0 + 遗留文件清理与 README 整理；该提交未触及代码文件，文中 file:line 引用与 f3c7000 勘探时一致）｜文档版本：计划稿（未开始执行）
> 执行原则已与需求方确认：范围=核心 Web+后端+pricetool；缺陷处置=修崩溃级+无感加固；前端验证=浏览器自动化 E2E。

## 一、总原则（硬性约束）

1. **业务逻辑绝对不变**：输入输出、分支逻辑、边界行为、异常反馈、时序效果与原代码 100% 一致，禁止隐性改动。唯一例外见「四、缺陷处置原则」中已批准的最小集合。
2. **接口与调用完全兼容**：函数签名、入参出参、结构体/字段、路由/事件、回调逻辑不发生破坏性变更。
3. **审查测试全覆盖**：重构后完成静态审查 + 动态用例测试 + 边界异常回归，无退化、无新增风险。
4. **所有问题可溯源可闭环**：每一处问题、修改、风险、测试结果逐条记录于台账（附录 A 为初始登记），闭环确认。

## 二、现状盘点（探索结论摘要）

- 规模约 8200 行。痛点排名：
  1. `static/app.js`（1749 行单文件 SPA，约 90 个全局符号，15+ 关注点混杂）；
  2. `app.py`（586 行：17 个路由 + 图片代理 + LRU 磁盘缓存 + 限流 + 锁 + 缩略图 + 启动逻辑）；
  3. `fetch_data.py main()`（约 115 行）；
  4. `pricetool/sync.py sync()`（约 205 行，全仓最长函数）；
  5. `config.py`（静态配置与分类逻辑混杂）。
- 已有保障：`shared/gacha.js` ↔ `gacha.py` 同种子对拍测试（`tests/test_engine.py`）；pricetool 自带 4 个单测（**未接入 CI**）；CI 仅跑 `tests/`；无 lint/格式化配置、无 requirements.txt。
- 平台副本：`miniprogram/` 与 `android/` 原生代码**本次不动**（其产物为生成物，由构建脚本重建）。

## 四、缺陷处置原则（已确认）

- **必修（崩溃级）**：未捕获异常（`/api/draw` packs 非数字 → 500；部分文件加载无异常保护）、资源泄露（`cli.py` 文件句柄、`.part` 残留文件）。
- **可做（无感加固）**："当前卡池数据下输出逐字节不变"的加固：HTML 转义、`state.pending` 显式声明、空包守卫。
- **禁止**：用户可见行为变化（文案、流程、时序、错误提示措辞、默认值变更）。
- 每处改动单独入台账（ID + 位置 + 理由 + 验证方式 + 状态），可单独回滚。

## 六、执行阶段

### 阶段 0：基线与安全网（不改业务代码）
1. 建 `docs/refactor/`：`LEDGER.md`（台账，初始内容=附录 A）、`CONTRACT.md`（R1-R9 明细）、`REVIEW_REPORT.md`、`TEST_REPORT.md`。
2. 新增 `tests/test_api_golden.py`：Flask test_client 对确定性端点做完整 JSON 快照断言；`/api/draw` 用固定随机种子做确定性输出断言 + packs 钳制边界（0/1/40/41）。
3. 扩充 `tests/test_engine.py` 对拍种子至 ≥20 种子 × 多规格（Python↔Node 同种子逐卡一致）。
4. 稳定性基线：500 次连续 `/api/draw`、200 次 `/img` 代理请求的耗时与内存基线。
5. 全部跑通并记录基线报告；后续每步回归必须全绿。

### 阶段 1：后端重构（每步一 commit，message 引用台账 ID）
1. **app.py 拆分**：`app.py` 保留入口（Flask app 创建、`_free_port`/pywebview/浏览器回退原样）；拆出 `server/` 包：`paths.py`（`_resolve_dirs`/`_ensure_writable_data`）、`httpcache.py`（`_fetch_allow` 限流、LRU 组、`_lock_for`、`_cached_fetch`、`_thumb_for`、`_fetch_detail`）、`api.py`（/api/* 路由 handler 原样搬移）、`media.py`（/img /thumb /icon）、`store.py`（user_store 读写+锁）。函数签名不变；PyInstaller 仍以 app.py 为入口自动分析本地导入。
2. **config.py 整理**：常量归组、魔法数命名（值不变）；`product_group`/`family_of`/`set_specs` 逻辑与签名不动；不拆文件。
3. **fetch_data.py**：main() 拆出 `split_151`/`expand_sets`/`write_manifest` 等私有函数；print 格式与退出码逐字保留。
4. **pricetool/sync.py**：sync() 拆为 `_sync_one_set`/`_topup_by_name`/`_refine_expensive` 等；日志逐字保留。
5. **重复逻辑**：`_dir_bytes/_dir_size` 合并；`atomic_write_json`/`_md5` 跨包**不物理合并**（风险>收益），加一致性对拍测试并在台账说明；`spec_brief` 三平台三实现保留，加"同输入三输出等价"测试。
6. **崩溃级修复**（按第四节原则逐条）：见附录 A 对应 ID。

### 阶段 2：前端重构（classic script 按序加载，不引入模块系统/框架/打包器）
1. **app.js 拆分**（index.html 按固定依赖顺序增加 `<script>`，DOM 结构与 id 不动）：
   `core.js`（常量/state/api/URL 与图片工具/`__imgFail`）→ `data.js`（DATA 层+热更新）→ `store.js`（持久化镜像+stats/spend/coll）→ `prices.js`（PRICE_MAP/priceOf/packValue/valueLineHtml）→ `ui-sets.js` → `ui-draw.js`（overlay 全套时序链原样）→ `ui-collection.js` → `ui-cardlist.js` → `ui-modals.js`（概率/详情/期望/战报）→ `app.js`（init 绑定+版本/更新/bridge+IIFE 启动）。
   顶层仅声明无执行，运行期依赖全局解析，拆分语义等价；`android/build_assets.py` 整目录复制自动带入新文件（干跑验证清单）。
2. **去重**（输出逐字节一致 + 字符串快照断言）：`collectionTile()` 模板工厂；`recordPackResult()`；`rarityCounts()`+`renderChips()`+`rrUpTo()`。
3. **魔法数命名化**：R4 常量表，值不变。
4. **死代码清理**（台账记录）：`BOX_SIZE`、`cardImage()`、`#themeInfo` 守卫引用。
5. **无感加固**：showDetail（1188/1198/1200-1203）、fillRarityFilter（1127）、RARITY_COLOR 样式注入处 escapeHtml（当前数据下渲染逐字节不变）；`state.pending` 显式声明；renderBoxSummary 空包守卫。
6. **style.css**：合并重复 `.pack-tab` 媒体查询规则（计算结果不变）、分节注释整理；动画参数逐条不动。

### 阶段 3：全量静态审查（6 维度，子代理并行）
产出 `REVIEW_REPORT.md`，每维度 0-100 分 + 问题清单（ID/位置/级别/处置/状态）：
1. **语法与工程规范**：`python -m py_compile` / `node --check` 全文件；命名、注释、文件结构、无废弃代码、无未用导入。
2. **逻辑一致性（必须 100 分）**：逐函数 git diff 对照 dev 基线——判断条件、循环逻辑、返回时机、中断逻辑、兜底分支、异常捕获顺序逐一核对，任何偏移打回重做。
3. **安全风险**：转义覆盖、`_SAFE` 路径校验、句柄泄露、并发锁/竞态、敏感信息回显（android keystore 回显超范围 → 仅台账记录）。
4. **性能与复杂度**：圈复杂度对比（重构前后）、无新增深嵌套、批量耗时对比基线不退化。
5. **可维护性**：单一职责、解耦、复用、可测试性、配置与代码分离、常量规范、容错完整性。
6. **兼容性**：R1-R9 逐项核对（路由/JSON/localStorage/window 契约/数据结构/旧场景行为）。

**通过线：总分 ≥90 且维度 2 = 100**，否则回修重审。

### 阶段 4：动态测试闭环
1. 后端 golden 全量回归（与基线逐字节比对）。
2. 边界异常矩阵：非法 set id（`../`、空、超长）、packs=0/1/40/41/-1/"3"/null、store/set 非 dict、缺失数据文件、空 prices、detail 未命中——错误码与 `{"error":...}` 文案逐字断言。

5. **前端 E2E（浏览器自动化）**：本地起服务，脚本覆盖：切页签/选卡池/单包与整盒拆卡（自动翻卡开关）/逐张与全部翻卡/页码导航/汇总条/再来一次/历史/收藏增删与导入导出/按价格排序/卡表筛选与无限滚动/概率/详情/期望成本/设置（主题/数据源/缓存）/Esc 与空格快捷键；逐步断言 DOM 状态并截图；另做拆分前后 `Object.keys(window)` 符号清单对比防全局遗漏。
6. 稳定性/性能：500 次 draw、200 次图片请求、50 次开合 overlay 循环；耗时/内存对照基线，无偶现报错。
7. `TEST_REPORT.md`：用例矩阵 × 结果 × 关联台账 ID。
